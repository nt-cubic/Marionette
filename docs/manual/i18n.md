# i18n 手册（中英双语）

一句话：`t(key, params)` + 词典片段体系。**转换规则正文在
`docs/guides/i18n-guide.md`**；本手册记坑与流程。

## 文件地图

| 想改什么 | 去哪 |
|---|---|
| 基础设施 | `src/lib/i18n.ts`（模块级 locale store + `t(key, params?)`，`{name}` 插值、`params.count` 选复数） |
| 词典 | `src/locales/zh-CN.ts` / `en.ts` 合并 `src/locales/parts/*.{zh,en}.ts` 片段 |
| Rust 侧 | `src-tauri/src/loc.rs` |

## 红线与坑

- **占位符必须 `{count}`**——t() 按 count 选复数、替换表只认 params 里的键；
  用 `{n}` 在两种语言都渲染成字面 `{n}`（PR 原版实锤，已修，别改回去）。
- **不进词典的例外**：`src/lib/mockData.ts`（浏览器预览假数据）、`src/locales/**`、
  代码注释。传给模型的指令文本若包含 UI 文案字符串，照常转换（UI 展示优先）。
- 新片段命名按域前缀（`fe-usage*`/`fe-uv2*`/`fe-seen*`/`fe-council*`…）——
  查 `src/locales/parts/` 现状对齐。
- **usage-smoke 在非中文系统会假红**：Node ≥24 默认语言来自 OS（本机 ja-JP），
  断言是中文——脚本开头 `await applyLocale("zh-CN")` 钉住。**别的脚本要断言文案
  时照做**。
- 贴边态文案（dock chrome）同样走词典；新增用户可见界面时 zh/en 两份一起加。

## 验证

```bash
npm run build          # 两份词典 key 对齐由 tsc 把关
npx tsx scripts/usage-smoke.mts   # 改 usage 文案时（含 applyLocale 口径）
```
