# 圆桌会议 — 用户指南(M1)

> 圆桌会议(多智能体集体审议,代码模块仍叫 Council)让多个模型**独立**
> 分析同一个任务、互相质询、修订立场,最后由主席模型综合成一份经过
> 评审的实施计划。M1 版本:完整的审议与计划流程;计划的自动执行
> (agent 落码)将在后续版本接入。

## 入口

- 左侧栏「聊天」区上方:**「圆桌」**
- 或 `Ctrl+K` →「打开圆桌会议」

圆桌页与普通对话完全独立:点开后标签行出现一枚「圆桌」伪标签
(与收纳盒同语义)。点对话标签切回会话,圆桌标签留着;× / Esc /
Ctrl+W 才关掉。

## 前置条件

圆桌的模型来自**模型共享引擎**(Magpie):

1. 左下角互联图标(模型共享)里启动引擎;
2. 至少配置一个模型来源(订阅登录或 API key,见「模型与来源」);
3. 召集页顶部的模型下拉来自引擎目录——空列表说明引擎未就绪,
   页面会给出引导。

## 团队模板(一键阵容)

设置页顶部的「团队模板」提供预设阵容,点「套用」即覆盖成员草稿(模型仍需自选,套用后一切可改):

| 模板 | 阵容 | 适合 |
|---|---|---|
| **标准圆桌** | 架构师 / 批判评审(主席)/ 算法分析 | 日常技术审议 |
| **身份局(趣味)** | 主公(主席)、忠臣、反贼、内奸、雌小鬼 | 对抗性最强的头脑风暴——反贼每轮必须提出**完整替代方案**(魔鬼代言人),内奸专戳边界情况与极端输入,雌小鬼毒舌但每句嘲讽必须紧跟技术论据(其产出还要经 lead 背书才被采信) |
| **垂帘听政(趣味)** | 幼太后(名义主席,建议配**弱**模型)、太师(必须配**最强**模型)、谏议大夫 | 弱主席 + 强背书的实验场:懿旨只能原样采纳太师标记「可颁」的结论 |
| **科研研讨** | PI(主席)、资深评审人(三轴打分)、方法论审查、文献调研、可行性分析 | 论文/实验设计把关;两个 contributor 座位产出清单式、可逐条核实 |

当前阵容也可「保存为模板」(存本机 `localStorage`,可随时删除)。模板只是起点——分层、角色、轮次套用后均可微调。

## 召集圆桌

| 配置 | 说明 | 默认 |
|---|---|---|
| 任务 | 要解决的问题:目标、约束、背景、期望产出。写得越具体,提案质量越高 | 必填 |
| 运行模式 | 仅审议(默认)/ 审议+执行 / 自治研发 | 仅审议 |
| 执行器 | 执行型模式下配置:执行 agent + 项目根目录(建议 git 仓库) | 无 |
| 成员 | 2–8 个;每个成员选一个模型 + 角色职责;★ 标记主席(综合与计划由主席产出) | 3 个角色模板 |
| 审议轮次 | 质询→修订的回合数;轮次内无待修订项会自动提前综合 | 2 |
| 并发上限 | 同时进行模型调用的上限 | 4 |
| 请求预算 | 模型调用次数上限,触顶即停(budget_exhausted) | 60 |

**建议**:至少选 3 个**不同模型**的成员(同模型多成员也合法,但
多样性是审议价值的主要来源);主席给推理强的模型。

## 身份局真对局(游戏模式)

运行模式选「**身份局游戏**」(或套用「身份局·真对局」模板):4-5 个成员作为玩家,系统暗中分配身份(主公亮明,忠臣/反贼/内奸只有自己知道),真打一局**简化三国杀**:

- 每回合轮到的玩家由其模型决策:出牌计划 + 一句面向全场的发言(可以演忠、可以指认、可以误导);
- 牌局面板实时显示各座位体力/手牌数/已亮身份;时间线即战报(行动、结算、发言全留痕);
- 主公阵亡或反贼内奸全灭即终局,**全部身份揭示**并生成战报;
- v1 简化:无武将技能/装备/延时锦囊;闪与濒死的桃由系统自动打出;回合上限 12;对局可暂停(重启后从当前局面续打)、可取消;消耗请求预算。

## 审议流程(自动进行)

```
主席简报 → 独立提案(互相不可见) → 交叉质询 → 修订回应
   ↑___________ 还有轮次且有未决分歧 ___________↓
→ 主席综合 → 实施计划 → 等待批准
```

- **独立提案阶段互相看不到对方的方案**(避免锚定),系统层面强制
  隔离——这不是提示词约定,是编排器构造输入时就不传入。
- 质询要求具体可检验:引用原文、指出问题;证据不足时模型应说
  「无法验证,建议实验 X」而不是猜。
- 分歧**不靠投票**:主席逐条裁决并给依据;裁决不了的进计划的
  「遗留不确定性」,每条附一个消解实验。
- 时间线按「轮次 · 消息类型」分组(简报 / 第 1 轮·提案 / 第 1 轮·
  质询 / …),成员名字颜色与左侧成员条一致。

## 执行与验证(执行型模式)

批准计划后:

1. **并行执行**:无依赖关系的任务并行跑,每个任务由所选 agent 在
   独立 git worktree 里完成(非 git 目录退化为串行并警告);
2. **顺序合并**:任务按计划顺序合并回项目目录;两个并行任务改了
   同一文件 → 冲突**显式上报**(任务标失败并列出文件),绝不静默覆盖;
3. **独立验证**:执行计划声明的验证命令(build/test/lint…),结果
   (含输出)进时间线;破坏性命令(git push / npm publish / rm -rf…)
   被拦截为「需人工」,不会自动执行;
4. **受限修复**:验证失败时,主席模型根据失败证据修订计划,只重跑
   受影响的任务;最多 3 轮,仍失败则 run 标失败并保留全部证据。

## 计划与批准

`计划待批` 状态下,页面顶部出现计划面板:

- 步骤清单(依赖关系、验收标准、建议负责角色);
- 遗留不确定性与验证命令(如 `cargo test` / `npm run build`)。

两个选择:

- **接受计划** → run 完成(M1 无代码改动;接受动作记入审计日志);
- **再议** → 保持待批状态(可取消后修改任务重新发起)。

## 运行控制

| 操作 | 效果 |
|---|---|
| 暂停 | 当前批次调用完成后停在阶段边界,状态「已暂停」 |
| 继续 | 从暂停的阶段恢复,已完成的部分(如简报、提案)**不会**重新调用 |
| 取消 | 立即停止,不再发起任何模型调用 |

**崩溃恢复**:进程重启后,进行中的 run 会显示「已暂停」——继续即
可从中断处恢复(已产出的提案/质询不会重跑,也不会重复计费)。

## 数据位置与审计

所有审议记录在 `~/.marionette/council/runs/<run_id>/`:

- `messages.jsonl` 全部发言(append-only,永不改写)
- `transitions.jsonl` 每次状态转移(含原因,如"用户取消")
- `plan.json` 最终计划;`spec.json`/`state.json` 配置与进度

删除 run(列表页垃圾桶)会移除整个目录;运行中的 run 需先取消。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 模型下拉为空 | 引擎未就绪:启动模型共享并配置来源 |
| run 停在「预算耗尽」 | 请求次数触顶;新建时调高预算 |
| 成员显示「失败:…」 | 该模型调用连续失败(额度/网络);run 会继续,该成员缺席后续轮次 |
| 计划生成失败(两次) | 模型未输出合法计划 JSON;换个主席模型重试 |
| 任务「失败:合并冲突:…」 | 两个并行任务改了同一文件;调整计划拆分或手动合并后重跑 |
| 验证命令被标「需人工」 | 命令匹配破坏性模式;人工确认后自行执行 |
| run「失败:验证失败且修复次数已用尽」 | 3 轮修复未通过;查看时间线的 Evidence 消息定位根因 |
| 全员提案失败 → run 失败 | 引擎/来源不可用,查看模型共享状态 |
