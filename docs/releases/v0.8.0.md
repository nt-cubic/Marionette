# Marionette v0.8.0：浏览器可读、图片可批注、Codex 窗口修正

单文件便携版，内置跨用引擎。下载双击即用，需要 WebView2 Runtime（Win11 与更新过的 Win10 自带）。

## 修好内置浏览器的页面读取

`browser_snapshot` 此前每次调用都会失败，agent 拿不到任何页面结构，所以「让 agent 读一下这个网页」这件事一直不成立。现在修好了：读页面、按元素编号点击和输入、截图、控制台日志都通。

- 修的是引擎安装那一步的判断。页面刚打开时引擎还没装进去，判断结果是一个特殊标记，旧代码把它当成正常数据解析，解析必然失败，于是「安装引擎」这段永远执行不到。现在先分辨答案类型再处理。
- 顺带修了导航后引擎上下文失效的问题，不再报「agent world is not in this document」。
- 修了一处会让整个窗口卡死的并发缺陷：两条浏览器调用同时挤进同一个标签时，界面的消息循环会被重入，窗口永久失去响应。现在同一时刻只放行一条，另一条得到一句「稍后重试」而不是把窗口冻住。这个缺陷在修改前的版本上同样能复现。
- 新增 `marionette-tools` 的三个工具（给 agent 用，界面上不出现）：
  - `browser_page_state`：返回网址、标题、滚动位置和**页面变更计数**。读两次比一比就知道页面动没动，比重新读一遍整棵页面树便宜得多。
  - `browser_page_ready`：页面是否已经稳定（加载完成、没有图片还在下载、字体不在加载中）。`settled: false` 就是「先等一下」，避免读到骨架屏。
  - `browser_set_value`：按元素编号直接写控件值——文本框、复选框、下拉框。它会派发页面自己的 input/change 事件，所以页面框架（React 等）能感知到；只赋值不派发事件的写法会静默失效。
- 这三个能力借鉴了 Cloudflare 开源的 kitesurf 浏览器引擎设计思路，实现是本项目自写。

## 图片查看器可直接批注并添加附件

- 在看图器里点「批注并添加」，打开已有的批注器；确认后直接把批注过的图片加进输入框附件。
- 同一张图反复批注只占一个附件位，新的标记覆盖旧的，不会堆出一排重复图片。
- 网络图片不提供批注（没有本地文件可写），按钮只在本地图片上出现。

## Codex 的上下文窗口按引擎真实值计算

- Codex 通过路由组换上游后，仍按它内建模型的 272K 窗口记账，导致 1M 的 DeepSeek 在约 246K 就自动压缩对话。
- 现在仅对「Codex × 引擎绑定」的会话，从引擎的模型目录读出真实上下文窗口并写进 Codex 启动配置；用户自己写的其它配置字段原样保留，目录里没有窗口就不注入，不编数字。
- 实测 1,048,576 的模型覆盖后可用量显示为 828,400，明显高于旧的 258,400。
- **已经在跑的会话需要重启一次 agent 进程**：这个配置只在进程启动时读取一次。

## 安装

```powershell
irm https://github.com/nt-cubic/Marionette/releases/latest/download/install.ps1 | iex
```

安装器会装进开始菜单并加入用户 PATH，不需要管理员权限；之后的应用内更新会原地替换程序。

- 文件：`Marionette.exe`
- 体积：25.14 MB
- SHA-256：`8AB42408A685E7CE9CCCDFE968382CD1165939FC084E4A6045B88E82F207E589`

从 0.7.x 升级无需迁移，数据目录与配置不变。
