# Marionette v0.8.2：员工模式、浏览器工具更可靠、引擎更新

单文件便携版，内置跨用引擎。下载双击即用，需要 WebView2 Runtime（Win11 与更新过的 Win10 自带）。

## 员工模式（Chief）

Marionette 从「多 Agent 管理器」往「一个人的助理团队」迈了一大步：侧栏顶部现在是你雇的**员工**，右栏是每位员工的档案——任务、记忆、承诺、通知策略。员工仍然是真实的 coding agent 会话，但被纳入一套治理框架：

- **员工档案**：每位员工有 pinned/state/history/journal 五层记忆与承诺账本；任务终态自动记 journal，员工提出的建议（proposal）可以在右栏直接采纳或驳回。
- **权限分级**：逐项目配置只读 / 审批写 / 预授权写，Computer Use 与自我修改独立开关，并被全局策略二次裁剪。员工会话强制只读时，要改项目只能派 worker 代劳。
- **急停**：Telegram「急停」、`/stop`、右栏暂停，三种入口都是注册表级——冻结所有员工的进行中任务、关闭 worker 的浏览器标签、撤销 Computer Use 共享窗口；恢复必须由你显式操作。
- **远程遥控**：Telegram 桥升级——通知、回复、远程批准、配对；本次还修了一批命令阻塞主线程的问题（全量任务清单/配置读取不再卡界面）。
- 控制工具只在员工会话里出现（16 个 `marionette_*` 工具，双保险 dispatch），普通对话不会拿到它们。

## 内置浏览器工具更可靠（ego-lite 批）

Agent 用浏览器时的四个高频痛点：

- **连续动作不再踩过期引用**：页面一动，元素编号就作废，agent 下一步就拿旧编号去点——现在有引用租约（ref lease），host 侧判死、页内侧裁决，失效时给真实原因（比如「用户批注顶掉了你的引用」），引导 agent 重拍快照而不是盲试。
- **批量动作（typed batch）**：点击、输入、等待可以编排成一批交给浏览器一次执行；快照只能做最后一步、权限拒绝永远停批，这两条规则写死，不会出现半批之后引用全换的坑。
- **等待与弹窗（waits + dialog）**：等元素出现/可连/可见的轮询走页内探针；JavaScript 弹窗（alert/confirm）不再被静默接管——用户始终有人工出口，agent 会收到「弹窗挡着」的明确答复而不是挂死。
- **`browser_help`**：agent 可以随时问「浏览器工具怎么用」，八个 topic 的自述（含 batch/waits 上线说明）从工具 schema 单一真源生成。

## 跨用引擎更新

- 内置 magpie 引擎从 v0.1.4232 升到 **v0.1.4406**（上游 174 个版本的累积），模型目录、配额、路由行为随上游同步；发布前合同套件 12 项全绿。

## 其它

- 收纳盒、项目搁板、窗口恢复的一批收尾修复；桌面通知增强。
- 文档目录重组（plans / pitfalls / guides / research 归位）。
- 进程内 Rust 引擎（magpie 替身）在 `engine-rust` 分支开发中，本版本不包含。

## 安装

```powershell
irm https://github.com/nt-cubic/Marionette/releases/latest/download/install.ps1 | iex
```

安装器会装进开始菜单并加入用户 PATH，不需要管理员权限；之后的应用内更新会原地替换程序。从 0.7.x / 0.8.0 升级无需迁移，数据目录与配置不变。
