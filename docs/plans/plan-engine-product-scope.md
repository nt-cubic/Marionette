# 引擎产品边界与转正路线

- 状态：**产品边界已落地**（2026-11-19）
- 审查基线：`engine-rust` @ `f8c0691d` + 本轮主线集成修复
- 关联合同：[`plan-engine-contract.md`](./plan-engine-contract.md)
- 现行行为：[`../CURRENT.md`](../CURRENT.md)、[`../guides/model-library.md`](../guides/model-library.md)

## 1. 结论

Marionette 不需要做一个完整 Magpie，也不需要兼容它的全部端点、路由策略、Agent 适配和运营功能。

内置引擎的产品目标是：**让用户已有的模型、API Key 和订阅登录，在 Marionette 当前支持的 Agent 中安全、稳定、可解释地跨用。** 只要这条用户旅程完整闭环，Rust 引擎就算“可以替代 Magpie”；Magpie 有而 Marionette 没有任何入口或消费者的能力，不进入验收范围。

因此采用以下判断：

1. **体验等价优先于字节级兼容。** 同一个模型目录、同一套凭据、三类对话协议、流式输出、工具调用、额度与错误提示在 Rust 引擎里成立即可。
2. **真实产品链路优先于功能清单。** 没有被 Marionette 前端、Agent 启动器或用户配置扫描消费的端点，不作为转正条件。
3. **数据安全高于 Magpie 兼容。** 读不懂的现有配置可以显示为空或报错，但绝不能覆盖用户原文件。
4. **路由必须可解释。** 用户选的是哪个来源、哪个账号、哪个模型，就应该按这个目标发起请求；不要在用户不知情时跨账号或跨计费来源切换。
5. **内置引擎的版本跟随应用。** Rust 引擎不保留单独下载、恢复出厂、升级 Magpie 的第二个版本系统。

按这个标准，Rust 引擎的**核心实现和默认发布门槛均已落地**：配置损坏不再可被覆盖，代理可在引擎重启后更新，usage 账本已隔离，Claude 订阅桥可转发图片，默认 SKU 已切到 `engine-rust`；Magpie 仅保留一个发布周期的显式回退。

## 2. 引擎在 Marionette 中的位置

引擎是“模型共享”的本地适配层，属于可选能力：

```text
已有 Agent 配置 / API Key / 订阅登录
                 │
                 ▼
        本地模型与来源目录
                 │
                 ▼
    Marionette 内置引擎（仅回环地址）
                 │
        ┌────────┼────────┐
        ▼        ▼        ▼
      Chat   Responses  Messages
        │        │        │
        └──── 已接桥 Agent ────┘
```

它承担五件事：

1. 读取和登记用户已经配置的来源，不破坏原文件。
2. 把来源里的模型以统一、可发现的形式展示给 Agent。
3. 在 OpenAI Chat、OpenAI Responses、Anthropic Messages 三类协议间做必要转译。
4. 让订阅登录在支持的 Agent 中跨用，并提供额度和余额读数。
5. 提供状态、诊断和可恢复的错误，不接管 Agent runtime，也不成为公开 API 平台。

引擎不负责会话、项目、工具执行、Agent 权限、模型聊天 UI 或云端同步；这些仍属于 Marionette 外壳和各 Agent 自己。

## 3. 用户旅程与最低承诺

产品是否接受一次引擎改动，先看它是否保护以下旅程。

| 用户旅程 | 用户预期 | 引擎的最低能力 | 用户可感知的验收 |
|---|---|---|---|
| 发现已有来源 | “不要让我重复录入 Key” | 扫描 Grok、Pi、OpenCode、Codex、Claude Code 等已适配配置；原文件只读 | 扫描后来源、警告和绝对路径可见；原配置字节不变 |
| 手动添加来源 | “自定义兼容接口也能接进来” | 名称、Base URL、协议、Key、模型 ID；支持无需认证的来源 | 检测只请求模型目录，不发送生成请求；保存后可立即被支持 Agent 发现 |
| 共享模型 | “我明确知道哪些模型借给了谁” | `/v1/models` 返回稳定 id、上下文窗口、输出上限、图片能力 | 模型菜单、共享开关、借给列表与实际路由一致 |
| 跨 Agent 使用 | “在 A 的界面里选到 B 的来源也能正常跑” | 三类入站/出站协议、流式、工具调用、reasoning、图片能力按模型宣告 | 支持矩阵内的 Agent 完成真实一轮；不支持的能力在发送前禁用或说明 |
| 使用订阅登录 | “我的 Claude / Codex / Grok 登录可以跨用，且不会误烧账号” | 只读发现登录态、账号身份可见、过期提示可行动 | 续期或限额失败时指出具体账号和修法；不静默换到另一个计费账号 |
| 查看额度 | “数字旧了要告诉我” | 订阅窗口、余额、失败缓存和 stale 标记 | 实时、缓存、离线快照三种状态文案不同；不把旧数字写成实时 |
| 遇到故障 | “我知道该修 Key、代理、额度还是模型能力” | 错误分层、日志脱敏、诊断导出包含引擎状态 | 同一个 401/429/超时不会都显示成“引擎挂了” |
| 启停与升级 | “共享模型坏了，不要拖死整个应用” | 懒启动、可停止、随应用退出、无孤儿进程 | 停引擎后 Agent 原生命中路径仍可用；共享模型给出可恢复提示 |
| 修改设置 | “代理改完，下次引擎请求就按新设置走” | 设置进入下一次请求或下一次启动，不使用永久进程单例旧值 | 修改代理后重启引擎即可验证，无需重启整个 Windows 会话 |
| 数据与隐私 | “我的 Key、对话和项目文件不会被误写或上传” | 本地回环、外站 Origin 拒绝、原子写、未知字段保留、日志脱敏 | 损坏配置不覆盖；浏览器页面不能盲调本地网关；导出日志不含秘密 |

这九条旅程就是产品侧的引擎合同；[`plan-engine-contract.md`](./plan-engine-contract.md) 中的 C1–C6 是它的技术落实。

## 4. 能力分级

### 4.1 P0：默认发布前必须有

| 能力 | 产品判断 | 验收口径 |
|---|---|---|
| 现有来源扫描 | 必须 | 扫描只读；文件不存在、不可读、缺环境变量、解析失败分别说明 |
| 自定义来源登记与改 Key | 必须 | 保存、更新、删除都不会丢掉未知字段；重复保存幂等 |
| 模型目录字段 | 必须 | `id`、上下文窗口、输出上限、图片输入能力完整；不知道就不编数字 |
| Chat / Responses / Messages | 必须 | 当前支持 Agent 实际消费的三类入口都有合同测试和真实一轮 |
| 流式与工具调用 | 必须 | SSE 不截断；tool call / tool result 跨轮不丢；错误保真 |
| 模型能力诚实宣告 | 必须 | 不能承载图片、reasoning 或工具时，不向 Agent 宣称这些能力 |
| Claude / Codex / Grok 订阅核心对话路径 | 必须 | 至少一个当前登录账号可完成正常对话；过期与限额错误可行动 |
| 额度、余额与缓存状态 | 必须 | force / cached / stale / offline 语义在 UI 可区分 |
| 本地安全边界 | 必须 | 仅回环监听；外站网页 Origin 403；请求体有硬上限；代理遵循用户设置 |
| 数据耐久 | 必须 | `providers.json` 原子写、备份、未知字段保留；任何读取失败都禁止覆盖原文件 |
| 生命周期 | 必须 | 懒启动、可停止、随应用退出；不要求用户先启动引擎才能使用原生 Agent |
| 诊断 | 必须 | 引擎状态、请求失败类别、版本和最近错误进入脱敏诊断报告 |
| 应用版本语义 | 必须 | 内置引擎显示为“随应用更新”；不出现 Magpie 下载/恢复出厂入口 |

### 4.2 P1：先由真实使用暴露优先级

这些能力影响大回合和边缘网络下的可靠性。若目标 Agent 的真实日常使用中会撞到，就升级为 P0；否则可在转正后继续补。

- 大请求体压缩与解码、512 MiB 级附件请求、慢连接与重试提示。
- Codex 长回合的出站压缩、断流续答和必要时的 WebSocket 路径。
- Anthropic `count_tokens`、上下文使用量准确拆分、`Retry-After` 与 `overloaded_error`。
- Claude 桥的图片直传、历史分块、会话续跑和工具 helper 完整度。
- 多账号自动切换仅在 UI 能显示“当前会使用哪个账号”时提供。
- HEIC、WebP、PDF、音频等附件转码按真实附件类型逐个补，不做全格式预承诺。
- 新 Agent 或新配置格式只在 Marionette 已正式接入该 Agent 后增加扫描器。
- 同一来源内的简单顺序回退可在用户能看到候选项时提供。

### 4.3 P2 / 条件项

- 多 Key 池、跨账号热备、跨供应商自动回退。
- 按价格、额度、速度、免费额度自动选路的策略引擎。
- Gemini 入站协议、更多订阅桥、更多额度探测供应商。
- 图片、文件、音频的跨供应商自动降级。
- 来源扫描对 DSH 动态 Cordis provider 等不稳定格式的覆盖。
- 用户自定义 Magpie CORS 白名单和网页客户端访问。

条件项只有在“界面上有明确入口、能展示结果、有对应真实用户需求、能自动化验证”时开工。

### 4.4 明确不做

- 完整 Magpie 端点面：embeddings、图片生成、音频、视频、Gemini 入站、搜索、MCP、管理 API、trace、concurrency、limit 等，没有 Marionette 消费者就不做。
- 作为公开或局域网模型服务器使用。
- 为第三方 SDK、任意 OpenAI 客户端或浏览器页面承诺完整 API 兼容。
- Magpie 的网页管理、Agent 管理、插件市场和完整运营面板。
- Magpie 的高级 `auto / usage / pace / free` 路由分类器和多级 fallback 策略。
- 跨账号静默轮换；尤其不能在不展示账号和计费来源时跨订阅自动切换。
- Kimi Code、MiMo Code 等当前不在 Marionette Agent 支持矩阵中的客户端适配。
- 为了“像 Magpie”而搬入上游 provider 清单、实验协议或未消费的字段。
- 在应用内维护第二个 Magpie 下载、更新和恢复出厂体系。
- 与 Magpie `usage.jsonl` 做逐字段双写兼容，除非 Marionette 的用量页明确消费该账本。

## 5. 关键产品取舍

### 5.1 支持矩阵取代“任何模型给任何 Agent”

“任意来源喂给任意 Agent”是方向，不应成为无边界的兼容承诺。产品应维护一张可验证矩阵：

- **正式支持**：当前 Agent、当前来源协议、核心能力组合已有自动合同和真实一轮验证。
- **基础支持**：文字流和基础工具可用；图片、reasoning、附件在 UI 标为不可用或受限。
- **尽力而为**：自定义 OpenAI 兼容来源；目录可用不代表所有厂商扩展都可用。
- **不承诺**：没有进入矩阵的 Agent、协议或能力，不出现在发送前的可选路径里。

这张矩阵应由代码和回归覆盖维护，而不是靠 README 的手写“支持一切”文案。

### 5.2 简单、确定的路由优先

Marionette 当前 UI 没有完整的高级路由编辑器。因此：

- 模型菜单里的“来源 / 模型”就是用户意图，默认直接请求该目标。
- Agent 内部别名组只用于保持原生模型名、effort 标记等兼容性，不暴露成一套新的路由器设置。
- 同一请求不得在用户不知情时改到另一个账号、订阅或计费来源。
- 失败转移必须有上限、可见原因和一致能力；把图片请求交给不支持图片的模型不算合理回退。

### 5.3 单账号是基线，多账号必须可见

Claude、Codex、Grok 的第一目标是“当前登录可跨用”。多账号池只有在以下条件同时成立时才做：

1. 用户能看到账号身份与当前选择。
2. 额度卡能按账号区分。
3. 自动切换会留下可解释的记录。
4. 不会把请求从个人订阅静默切到另一份付费账号。

### 5.4 能力缺失必须提前表达

如果某个共享路径不能传图片、工具、reasoning 或附件：

- 不要先让用户选中、发送，再由上游报一个晦涩错误。
- 模型目录应如实宣告能力。
- Agent 的原生路径仍可保留这些能力，不能因为引擎不支持就影响原生模型。
- 受限组合应显示“文字可用，图片不可用”一类具体说明。

### 5.5 一个应用，一个版本号

Rust 引擎编进 `marionette.exe` 后，用户不应该再理解“应用版本”和“引擎版本”谁管谁。产品文案采用：

- `内置引擎 · 随应用更新`
- `模型共享未启动 / 启动失败 / 正在运行`
- 需要恢复时走应用自身的更新或重装流程

Magpie 的下载更新、恢复出厂和版本提示只在 Magpie SKU 出现。

## 6. 当前 `engine-rust` 的产品判断

### 6.1 已证明可工作的部分

截至审查快照：

- Rust 全量测试 `1187 passed / 0 failed / 5 ignored`。
- 同一份合同套件对 Magpie 种子与 Rust 引擎的 C1–C6、D1–D10 全部通过。
- Rust SKU 能以进程内线程启动，端口由 `marionette.exe` 持有，没有独立 Magpie 子进程。
- `/v1/models`、非流式 Chat、SSE Chat、工具调用、三类协议入口及订阅额度面已有实现和测试。
- 外站 Origin 防护、gzip/zstd 入站、512 MiB 体上限、request-id / `Retry-After` 透传等早期高风险项已补。

这说明“Rust 引擎能不能运行”已经成立，剩下的是产品是否敢把默认路径交给它。

### 6.2 审查时发现的转正阻断项与处理状态

| 优先级 | 发现 | 用户影响 | 处理要求 |
|---|---|---|---|
| P0 | `store.rs` 读取或解析 `providers.json` 失败时退成空表，后续编辑会写回空表加新项 | 损坏或短暂不可读时可能覆盖用户全部来源与 Key 配置 | **已修**：读失败/坏 JSON/BOM/权限错误/并发外部修改都禁止写回；原子替换并保留 `providers.json.bak`，有定向测试 |
| P0 | 分支尚未合入最新 `master` 产品改动 | 默认切换可能带入旧工作区、Agent 生命周期和 UI 行为 | **已修**：Rust 引擎与合同/文档合入当前主线；`master` 的 Magpie 种子与无关上游冲突保持主线版本 |
| P1 | 出站代理用 `OnceLock` | 应用内修改代理后，即使重启引擎仍可能走旧代理 | **已修**：改为可替换状态；每次拉起进程内引擎重新注入，测试覆盖连续替换与显式关闭 |
| P1 | 引擎 `usage.jsonl` 与 Magpie 同路径但字段不同 | 双 SKU 来回运行时账本混写、历史读取不一致 | **已修**：Rust 改写 `engine-usage.jsonl`；首次打开只迁移严格可识别的旧 Rust 行，Magpie 原文件不删不改 |
| P1 | Claude 订阅桥不能直传图片 | 跨用 Claude 订阅时视觉任务能力受限 | **已修**：base64/URL 图片按原位置进入 stream-json；目录宣告图片能力，工具结果图片同样转发 |
| P1 | Codex 长回合与 Magpie 的压缩/传输路径不完全相同 | 大会话在特定网络或超长回合下可能断流 | 保留 gzip/可选 WebSocket/断流续答并纳入合同与全量测试；真实超长回合继续作为回退周期观察项 |

本轮处理后的默认发布形态：`engine-rust` 是 Cargo 与便携构建默认值；
`MARIONETTE_ENGINE=magpie` 构建一个发布周期的 embedded Magpie 回退。

### 6.3 不构成转正阻断的缺口

以下差异可以保留：

- Magpie 有而 Marionette 不调用的 HTTP 端点。
- 高级路由分类器、复杂组路由和多账号热备。
- 未接桥 Agent 的客户端模拟、设备码登录和专用协议。
- 不消费的 trace、concurrency、管理统计和完整 usage 字段。
- 图片、音频、视频生成和公网/局域网服务能力。

这些是另一款产品的能力，不是 Marionette 的未完成核心。

## 7. 用户界面规则

### 7.1 “模型共享”页应回答的问题

页面不需要向普通用户展示 `providers.json`、group、route id 或协议细节。它应回答：

1. 检测到了哪些来源？
2. 哪些来源缺 Key、登录过期或目录读取失败？
3. 哪些模型已共享，借给了哪些 Agent？
4. 当前来源的额度是实时、缓存还是旧快照？
5. 引擎正在运行、未启动还是启动失败？失败后用户下一步做什么？

### 7.2 错误必须指向责任层

建议统一为以下用户可见类别：

| 类别 | 示例文案方向 | 用户动作 |
|---|---|---|
| 引擎未启动 | “共享模型当前不可用；原生模型不受影响” | 启动引擎 |
| 上游认证 | “该来源的 API Key / Claude 登录已失效” | 更新 Key 或重新登录对应 Agent |
| 额度或限流 | “该账号已达窗口上限；额度数字为 30 秒前快照” | 等待、换模型或明确换账号 |
| 网络或代理 | “无法连接来源；检查当前代理设置” | 修改代理并重启引擎 |
| 模型能力不匹配 | “当前模型不支持图片 / 工具” | 换模型或改走原生路径 |
| 协议转译失败 | “该 Agent 与本来源的协议组合不可用” | 切回原生模型，导出诊断 |
| 配置损坏 | “来源配置无法读取；为保护原文件，编辑已停用” | 打开备份 / 诊断，不自动覆盖 |

### 7.3 状态与额度

- `running`、`stopped`、`failed` 只用一套状态词，不在不同面板各写一套。
- 额度卡必须标 `实时`、`缓存` 或 `旧快照`；旧快照附时间。
- “检测来源”只验证模型目录，不发送生成请求，不消耗一轮对话额度。
- 新增来源、改 Key、删除来源都要有明确成功/失败反馈。

## 8. 转正验收

默认切换 Rust 引擎前，以下检查应全部通过。

### 8.1 数据与安全

- 损坏 JSON、BOM、空文件、无权限、读取中断都不会覆盖原 `providers.json`。
- 最后正确备份可恢复；未知 Magpie 字段在保存后保留。
- 外站网页请求全部 403；本地 Agent 与无 Origin CLI 正常运行。
- 诊断报告和错误文本无 Key、OAuth token、Authorization 头或 home 路径泄露。
- 引擎停止、崩溃和正常退出都不留孤儿子进程。

### 8.2 来源与模型

- 扫描现有五类用户配置后，原文件哈希不变。
- 自定义 Chat、Responses、Anthropic 来源各完成一轮真实验证。
- `/v1/models` 的窗口、输出上限、图片模态与 Agent 菜单一致。
- 共享开关、来源隐藏、排序和“借给哪些 Agent”在重启后保持。

### 8.3 Agent 真机矩阵

对当前正式接桥的 Agent 至少覆盖：

- Chat 入站一轮：普通文本、SSE、工具调用。
- Responses 入站一轮：Codex 模型目录、上下文窗口、工具调用。
- Messages 入站一轮：Claude Code 的 stream、tool use、`count_tokens`。
- 支持图片的共享模型完成一张本地图片输入。
- 订阅登录过期、额度耗尽、网络断开各出现一次，并显示可行动错误。

矩阵的“正式支持”项必须在发布前重新跑；未重跑的项不能靠上一次结果继续宣称支持。

### 8.4 生命周期与设置

- 冷启动不启动引擎也能进入应用、打开原生对话和切换原生模型。
- 首次使用共享模型时懒启动成功；停止后可再次启动。
- 修改代理后重启引擎，新代理生效。
- 应用退出、系统关机和强制结束情况下，引擎线程和订阅桥子进程可收敛。

### 8.5 发布集成

- `engine-rust` 合入当前 `master` 后，默认构建、Rust SKU 构建、前端构建和全量 Rust 测试全绿。
- 合同套件分别对 Rust 与 Magpie 跑绿。
- Windows 便携版、安装版、开始菜单快捷方式和升级路径使用同一版本号。
- Rust SKU 不出现 Magpie 下载/恢复操作；Magpie SKU 行为不回归。

## 9. 发布路线

### 阶段 0：范围定稿

- 接受本文件的能力分级和“明确不做”列表。
- 将当前接桥 Agent 作为第一版支持矩阵，不因 Magpie 上游新增能力自动扩容。

### 阶段 1：P0 修口（已完成）

- 修复配置损坏时的覆盖风险。
- 修复代理设置无法更新。
- 决定并隔离引擎 usage 账本。
- 合并最新主树，跑全量测试与当前 Agent 真机矩阵。

### 阶段 2：回退周期（随本次默认切换开始）

- Rust 已是默认；Magpie 作为显式回退构建保留。
- 通过日常使用和自愿诊断收集失败类型；不以遥测默认开启为前提。
- 只修“支持矩阵内的真实故障”，不因上游功能列表膨胀改范围。

### 阶段 3：默认切换（已完成）

- 阶段 1 的阻断项已消失；回退周期用于观察真实长回合和新 Agent 组合。
- 默认构建已切到 Rust；Magpie 保留一个发布周期作为显式回退 SKU。
- 用户无需理解 SKU；设置页只显示内置引擎状态。

### 阶段 4：退役 Magpie 运行路径

- 再经过一个稳定发布周期后，从发布构建中移除 Magpie 载荷、下载更新和 factory restore。
- 配置兼容和旧版本回退说明保留在发布文档中。

## 10. 建议拍板项

建议按以下默认答案推进评审：

1. **支持范围**：只承诺 Marionette 当前已接桥且能真机验证的 Agent；Kimi Code、MiMo Code 等不进入本版验收。
2. **Magpie 兼容**：保留 `providers.json` 读兼容、未知字段保留和原子写；不追求 Magpie 全端点/全路由兼容。
3. **高级路由**：不做 `auto / usage / pace / free` 分类器和静默跨账号轮换。
4. **多账号**：先保证当前账号可用且错误透明；账号池仅在 UI 能展示身份与计费归属时再开。
5. **订阅桥**：Claude / Codex / Grok 正常对话属于核心；图片和长回合边缘先按真实使用升级，不以完整 Magpie 清单预先承诺。
6. **转正条件**：先修配置数据安全、代理生效、usage 隔离和主树合并，再谈默认切换。
7. **版本策略**：Rust 引擎只有一个版本号，随应用发布和更新。

这份边界的核心不是缩小野心，而是把工程投入集中到用户真正会经过的路径：来源能安全进入、模型能准确出现、Agent 能可靠调用、失败能自己解释、应用能持续升级。
